Reviving NASP

NASP is a published pipeline that researchers use to compare bacterial genomes, for example to tell how closely related outbreak samples are. Its install package had been broken for years. Working with Dr. Jason Sahl, the paper's first author, I found out why, fixed it, and got the fixes shipped to bioconda.

The problem

It installed perfectly and didn't work

Running conda install nasp finished without a single error. Every quick check I could run without actually using the tool also passed. But the first time NASP tried to process an alignment, it crashed.

Every alignment in NASP passes through a tool called samtools, and the samtools version the package pinned couldn't even start. So the pipeline died before it processed a single read, and nobody had been able to publish a fixed build since 2020.

The lesson that shaped the whole project: a dry run only checks that packages fit together. It never runs them. From then on I tested by actually running things.

Diagnosis

What was actually broken

Root cause 1 · The crash

A samtools build missing a library

The recipe pinned samtools below 1.3, which picked version 1.2. That build needs a system library (ncurses) but never declared it, so nothing installed it and the program couldn't load.

Fix: pin samtools 1.1 instead. Its build declares the library correctly and still understands NASP's commands. I tested this directly against four samtools versions.

Root cause 2 · No new builds

One line of shell broke every build

The build script overwrote NASP's Go module file with a one-line version that dropped a dependency. Older Go versions quietly fixed that. Go 1.16 made it a hard error, so the build broke without anyone changing NASP.

Fix: delete that one line.

Root cause 3 · Hidden

A blacklist nobody remembered

When that build failure hit bioconda's 2021 mass rebuild, NASP was added to a list of recipes the system stops trying to build. That's why the failure stayed invisible for years.

Fix: remove NASP from the blacklist.

Root cause 4 · Modern Python

A removed Python module

NASP found its own bundled files with pkg_resources, which setuptools deleted. I pinned down exactly when: version 81.0.0 has it, 82.0.0 doesn't.

Fix: a temporary version pin, then a real code fix using Python's built-in importlib.resources at all 4 places NASP used it.

Root cause 5 · Modern samtools

The fix that silently failed

NASP sorts alignments with an old samtools command that newer versions reject. The obvious replacement looked fine, but when I tested it on samtools 1.1 it wrote no output file and still reported success. A small extra flag (-T) makes it work on 1.1, 1.9, and 1.24. This is why I tested every fix instead of trusting it.

Proof

How I know it works

Same answer, byte for byte

  • Ran the full pipeline on NASP's own example dataset: alignment, SNP calling, an external genome, and the duplicate-region check
  • Ran it three ways: the original code, my fixed code, and my fixed code on the newest samtools
  • All three produced output byte-identical to each other and to the expected results in the repository: 3,977 positions and the same 5 SNPs

How I tested

  • Every test ran in a fresh Ubuntu container with nothing carried over, and every run's raw output is saved
  • No claim without a command behind it. That rule disproved 8 assumptions, including the starting premise of the whole project
  • Caught two mistakes in my own method: Linux versions solved from a Mac came out stale, and a piped command was hiding a failure. I re-ran both
  • Checked the recipes with bioconda's own linter and build tools before submitting
Judgment

What I left out on purpose

Some problems aren't packaging bugs. Fixing them would change which SNPs NASP reports, so they're research decisions for the lab, not for me.

Retired, with approval

The SAMtools SNP caller

Its 2013-era command fails on every bcftools version still packaged. Rewriting it would change results, so with Dr. Sahl's approval I removed it from the menu instead.

Needs validation

Moving to GATK 4

NASP's caller doesn't exist in GATK 4. Its replacement calls SNPs differently, so switching would need scientific revalidation.

Untested

MUMmer 4

It looks compatible on paper, but its defaults changed. MUMmer 3.23 works, so I left it rather than guess.
